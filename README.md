# Dawoni (다워니)

학원 강사가 이미 구독 중인 AI의 공식 CLI(Antigravity `agy`, Claude Code, Codex CLI)를 일꾼으로 부려
수학·과학 문항 DB화, 파라미터 그림, 해설·동형문제, 서술형 채점, DOCX 출력을 돕는 도구.

설계와 진행 순서는 [PLAN.md](PLAN.md), 진행 기록은 [PROGRESS.md](PROGRESS.md)를 본다.

## 개발 환경

```bash
uv sync
uv run pytest
uv run ruff check .
uv run pyright
```

- Python 3.15 (`.python-version`), Node 26 (프론트엔드, M7부터)
- 수식 → Word 변환용 pandoc은 `pypandoc-binary`로 함께 설치됨
- 실제 AI CLI를 호출하는 테스트는 기본 제외: `uv run pytest -m agent`

## 화면 (M7)

```bash
cd frontend && npm install && npm run build   # 결과는 dawoni/web/ (커밋하지 않음)
uv run dawoni ui                               # 앱 창 (macOS: pywebview, Windows: Edge 앱 창)
```

- 서버는 `127.0.0.1`에서만 열리고, 실행할 때마다 새 토큰을 만든다 (다른 웹사이트가 부르지 못함).
- 화면 개발: `uv run dawoni ui --no-window`로 서버를 켠 채 `cd frontend && npm run dev`,
  터미널에 찍힌 주소의 `/login?t=…` 부분을 `http://localhost:5173/login?t=…`로 열기.
- 프론트 검사: `cd frontend && npm run typecheck && npm test`
- 실제 자료 회귀 테스트: `tests/test_real_layouts.py` — `real_data/`(git 제외)에 실측한 교재·기출이 있을 때만
  돈다 (AI 없음). 레이아웃·챕터 제안을 고친 뒤 꼭 돌린다. 새 자료를 실측하면 기대값을 더한다.

## 서술형 채점: 해설지 기준 루브릭

```bash
uv run dawoni ingest exam 시험지.pdf --title 중간고사 --scope <범위ID>   # 해설 쪽은 자동으로 찾음 (--key-pages 6 | none)
uv run dawoni exam key <시험ID> 해설지.pdf [--pages 6]                   # 해설지가 따로 있을 때
uv run dawoni exam key-confirm <시험ID> --by 김선생                        # 해설지 판독을 원본과 비교한 뒤
uv run dawoni exam rubric <시험ID>                                       # 해설지 넓히기 (AI 호출 문항당 1번)
uv run dawoni exam rubric <시험ID> --ai-solve                            # AI 풀기 (해설지 검산): 풀이·비교·검토·검산
uv run dawoni exam show <시험ID> -q 3                                    # 해설지·AI 풀이·비교·정답 후보·넓힌 표현
uv run dawoni exam candidates <시험ID> -q 3                              # 후보를 정하기 전에: 학생 답이 어느 쪽인지 (판독 후)
uv run dawoni exam approve <시험ID> -q 3 --by 김선생 [--accept A1 E1] [--reject A2]
```

- **기본은 해설지 넓히기** (2026-10-31): 해설지가 있는 문항은 루브릭 역할 호출 한 번(문항 + 그 문항의
  해설지 + 짧은 범위, 2분, 수리 1번)으로 해설지의 정답·배점·부분 점수 논리를 그대로 펼친 루브릭을 만든다.
  서술형 소문항은 해설지와 **같은 근거·같은 결론**의 다른 표현을 'AI가 넓힌 표현'(E1, E2 …)으로
  제안한다 — 강사가 인정한 것만 채점 기준에 들어간다. 해설지와 값·결론이 다른 답은 넓히지 않는다.
  AI 풀이·검토·검산 호출이 없어, 같은 2소문항 예제에서 호출 8번(프롬프트 약 1.5만 토큰) → 1번(약 0.27만).
- 해설지에 오타가 걱정되면 화면의 **"AI 풀기 (해설지 검산)"**(`--ai-solve`): 아래의 예전 경로
  (AI가 해설지를 보지 않고 먼저 풀기 → 비교 → 다른 세션 검토 → 독립 검산). 해설이 없으면 먼저 푼다.
  해설지가 없는 문항은 언제나 예전 경로(먼저 "해설 만들기").

- 시험지 PDF 뒤의 해설 쪽("부분 점수", "정답 및 해설" 표시)은 문항 영역에서 빼고 **해설지**로 읽는다:
  소문항마다 답·해설·부분 점수 표기(항목별 점수 / 없음 / 범위)·0점 조건.
- 해설지는 새 세션에서 **두 번** 읽어 숫자를 비교하고, 다른 소문항은 '원본 확인'으로 표시한다
  (실측: 한글은 그대로 옮기면서 수식의 숫자를 바꿔 읽음). 강사가 원본과 비교해 확인·수정한다.
- 문항의 소문항((1), (2), (1)① …)마다 배점과 유형(서술형/단답형)을 함께 저장한다.
- (AI 풀기) AI는 해설지를 **보지 않고** 먼저 푼다 → 루브릭은 해설지의 정답·배점·부분 점수를 기준으로 만들고,
  소문항마다 AI 답과 비교한다: 같음 / AI 오답(해설지 따름) / 다른 정답 후보 / 해설지·문제 의문.
  두 답이 다르면 **둘 다** 문제에 대입해 독립 검산한다 — 해설지 답이 검산을 통과하지 못하면 강사에게
  알린다 (실측: 해설지가 그림과 다른 기호로 답을 적은 경우).
- 소문항 배점 합, "부분 점수 없음"이면 항목 하나, 항목별 점수의 합은 코드가 검사한다.
  다른 AI 세션이 루브릭이 해설지를 지키는지 한 번 더 검토한다.
- 해설지와 **다른 답**은 '정답 후보'로만 둔다 (문제에 대입해 독립 검산). 강사가 인정하기 전에는
  점수를 주지 않고, 학생 답이 후보와 같으면 그 채점을 '검토 필요'로 둔다. 같은 답에 이르는 다른
  풀이·설명은 'AI 제안'으로 표시해 인정한다.
- 후보를 정하기 전에, 판독한 학생 답이 **해설지 답 / 후보 / 그 외** 중 어느 쪽인지 몇 명씩, 예시 답안과
  함께 본다 (`exam candidates`, 화면의 "학생 답과 비교"). AI에는 이름 대신 학생1, 학생2 …만 보내고,
  결론 문장은 판독문에서 그대로 인용해야 한다 — 인용이 판독문에 없으면 다시 시킨다
  (실측: 그냥 "채점해"라고 맡기면 학생의 "㉢이 밝다"를 해설지에 맞춰 "㉠이 밝다"로 고쳐 읽었다).

## AI 역할과 모델 등급

작업 흐름은 결정적인 파이썬(`ContextEngine` + 작업 흐름)이 정하고, AI 호출 하나하나는 **역할** 하나가
맡는다. 역할 지시서는 `dawoni/roles/<역할>.md`(영어, 짧게 — 호출마다 60~250토큰)이고 계약 다음,
과업 앞에 들어간다. 역할 지시서에는 그 역할 전체에 걸친 버릇과 **실제 자료에서 본 실수**(예: ㉠을 ㉢으로
고쳐 읽음)를, 과업 템플릿에는 그 작업의 절차를 적는다 — 같은 말을 두 곳에 쓰지 않는다. 강사·학생이 읽는 출력은 계약에 따라 언제나 한국어(서술형, 부분 점수, ㄱㄴㄷ 그대로).
등록부 `dawoni/roles/__init__.py`가 역할마다 등급·수리 횟수·시간·프롬프트 예산·그림 크기를 정하고,
`calls.jsonl`에 역할·등급이 남는다 — 며칠 써 보고 오류가 쌓이는 역할만 등급을 올린다.

| 역할 | 맡는 작업 | 등급 | 수리 | 예산(토큰) | 그림 긴 변 |
|---|---|---|---|---|---|
| 쪽 판독 page_reader | extract_questions | standard | 2 | 40k | 1568px |
| 해설지 판독 key_reader | extract_answer_key | standard | 2 | 40k | 1568px |
| 손글씨 판독 handwriting_reader | transcribe_answer | standard | 2 | 20k | 그대로 |
| 표지 판독 cover_reader | read_cover | fast | 1 | 8k | 1568px |
| 개념 추출 concept_extractor | extract_concepts | standard | 2 | 50k | — |
| 루브릭 rubric_builder | expand_key_rubric(수리 1), derive/audit/suggest_rubric | standard | 2 | 30k | — |
| 채점 grader | grade_answer | standard | 2 | 24k | — |
| 풀이·검산 solver_verifier | solve_question, check_answer | strong | 2 | 16k | — |
| 문제 만들기 problem_maker | gen_*, propose_extensions, draft_extension | strong | 2 | 24k | — |
| 그림 figure_maker | figure_spec, figure_compare | standard | 2 | 12k | 1568px |
| 강의 요약 lecture_summarizer | lecture_chunk, lecture_summary | fast | 2 | 40k | — |
| 가벼운 도우미 light_helper | match_candidates, refine_rule | fast | 1 | 24k | — |

- **예산**은 글자로 된 프롬프트의 추정치(이미지 제외). 실제 기록(`calls.jsonl`)에서 가장 큰 것은 해설지
  판독 약 1만, 쪽 판독 0.6만, 강의 0.8만, 채점 0.27만 — 넘치면 줄일 수 있는 레이어(기준 예시 → 범위 →
  자료)부터 줄이고 그래도 넘치면 멈춘다(조용히 자르지 않음). 호출 하나의 전체 토큰은 2만~15만이라
  **그림과 생각**이 대부분이다 → 호출 수를 줄이고(해설지 넓히기, 미리 맞추기) 그림을 줄이는 쪽이 효과가 크다.
- 역할마다 보내는 것: 그 문항과 그 문항의 해설지만(시험 전체를 다시 보내지 않음), 해설지 넓히기는 범위의
  짧은 판본(이름만), 인정 안 된 넓힌 표현·정답 후보는 채점 기준에 넣지 않음, 학생 답 비교는 정해지지 않은
  학생만.
- **등급 → 모델**은 설정(`config.json`의 `tiers`, 화면 "연결 · 설정 → 5. AI 역할과 모델 등급")에서 고친다.
  칸이 비면 그 AI 설정의 모델을 쓴다(모델 이름을 짐작하지 않음). 역할 등급 바꾸기는 `role_tiers`.

  | 등급 | agy (Gemini) | claude | codex |
  |---|---|---|---|
  | fast | gemini-3.8-flash-low | claude-haiku-5-5 | effort low |
  | standard | gemini-3.8-flash-medium | claude-sonnet-5-5, effort medium | effort medium |
  | strong | gemini-3.8-flash-high | claude-sonnet-5-5, effort high | effort high |

  agy 이름은 `agy models` 목록(2026-10-31)에서 골랐다. 더 높은 것(gemini-4-argon-high, claude-opus-5-5)은
  한도를 빨리 써서 기본으로 두지 않았다. claude·agy는 `--effort`, codex는 `-c model_reasoning_effort=…`.
- **다른 AI로 저절로 넘어가지 않는다**: 한도 초과·로그인 필요·미설치면 "agy 사용 한도 초과 — 다른 AI로
  계속할지 정하세요"로 멈추고, 화면에 "claude로 계속"(기본 AI 바꾸기)·"항상 자동 전환" 단추가 뜬다.
  2026-10-30에 agy 한도가 끝나자 호출 103건(약 340만 토큰)이 조용히 claude로 넘어가 claude 주간 한도까지
  다 쓴 일이 계기. 자동 전환은 설정 `auto_fallback`.
- **토큰 줄이는 무료 도구**
  - 그림 줄이기(Pillow, 이미 있음): 역할별 긴 변 상한, JPEG가 PNG의 70%보다 작을 때만 JPEG. 실측(실제 자료,
    AI 없음): 해설지 쪽 170dpi 1405×1989 → 1108×1568, 스캔 쪽 2866×2024 → 1568×1107, 시험지 쪽
    1821×2635 → 1084×1568. claude는 어차피 1568px로 줄여 보므로 손실 없음. Gemini는 768px 타일 수로 추정하면
    시험지·스캔 쪽 12 → 6타일(약 3,100 → 1,550토큰), 해설지 쪽은 원래 6타일이라 그대로. 스캔 파일 718KB →
    182KB(JPEG). 손글씨는 작은 계수를 잘못 읽은
    사례("5h"→"h")가 있어 줄이지 않는다.
  - 학생 답 미리 맞추기(`rapidfuzz`): 결론 줄에 해설지 답·후보 중 **하나만** 그대로 있으면(글이 같음 /
    값이 같고 좌변도 같음 / 숫자 없는 긴 글은 95점 이상) AI 없이 정하고, 남은 학생만 AI에 보낸다.
  - 무료 로컬 OCR(선택, `uv sync --extra local-ocr`): RapidOCR로 스캔 시험지·교재 PDF에 보이지 않는
    글자 층을 입혀 디지털 PDF와 같은 길로 읽는다. onnxruntime이 아직 Python 3.14용까지만 있어 3.15에서는
    설치되지 않는다 — 없으면 스캔 PDF는 예전처럼 거절(설치 안내 포함).

## 여러 학생 답안지 한 번에 (스캔 PDF)

```bash
uv run dawoni exam scan-batch <시험ID> 답안지.pdf --per-student 3 --classes TSS1,TSS2,MSS1-J,MSS1-K [--cross]
uv run dawoni exam compare <시험ID>     # 채점한 답안지를 넣었을 때: AI 점수 ↔ 표지의 강사 점수
```

- 학생마다 같은 쪽 수(첫 쪽은 표지)로 나눈다. 표지에서 이름(동명이인 알파벳까지)·반·학교와
  강사가 적은 문항별 점수, 돌려 세울 각도를 읽는다. 반 목록을 주면 손글씨 "1TSS"·"M1J"도 목록에 맞춘다.
- 판독문은 줄마다 소문항((1), (1)② …)을 표시한다. 학생마다 따로 저장해 중간에 멈춰도 이어서 한다.

**복합기 스캔본**: 설정 → "복합기 스캔 폴더"에 주소(예: `smb://192.168.0.100`)와 사용자 이름을 넣고, 답안 탭의
"복합기 스캔본 열기"를 누르면 복합기 폴더와 작업공간의 `스캔본` 폴더가 함께 열린다. 비밀번호는 다워니에
저장하지 않는다 — 처음 연결할 때 Finder·탐색기가 묻고 키체인·자격 증명 관리자에 저장한다.

**강사별 문항 분담** (답안지 한 쪽에 한 문항):

```bash
uv run dawoni exam answer-pages <시험ID> 1=2 2=3 3=4 4=5        # 표지가 1쪽
uv run dawoni exam scan-batch <시험ID> 답안지.pdf --per-student 5 --covers-only   # 표지는 한 번만
uv run dawoni exam scan-batch <시험ID> 답안지.pdf --per-student 5 -q 2            # 2번 담당: 3쪽만
uv run dawoni exam grade <시험ID> -q 2
```

맡은 문항의 쪽만 그 문항만 두고 판독하므로 강사마다 자기 구독(토큰)으로 나눠 쓸 수 있다. 함께 쓰기
작업공간이면 표지 정보·판독문·채점이 모두 같은 폴더에 모인다.

**강사 채점으로 루브릭 보완**: 몇 명을 직접 채점해 소문항 점수를 넣으면(채점 검토 창의 "소문항 점수로
확정", 또는 `exam teacher-scores 강사점수.csv` — `학생,문항,소문항,점수,이유`) AI와 다른 소문항이 기준 예시가
되고, `exam suggest-rubric -q N`이 그 사례로 루브릭 개선안을 낸다. 판독문으로 설명되지 않는 강사 점수는
판독 오류 의심으로 따로 알리고 규칙으로 만들지 않는다. 다시 채점해도 강사가 확정한 점수는 덮어쓰지 않는다.

## 유튜브 강의 요약 (M12)

```bash
uv run dawoni lecture summarize "https://youtu.be/…" --scope <범위ID> [--pages 2] --docx
uv run dawoni lecture list | show <요약ID> | export <요약ID>
```

- 영상·음성은 받지 않고 **자막(자동 자막 포함)만** 읽는다. 자막이 없는 영상은 아직 안 됨.
- 약 20분 구간마다 노트 → 합쳐 A4 1장(또는 양면 1장, 2단) 요약. 구간 노트는 저장해 두므로
  긴 강의가 중간에 실패해도 다시 하면 끝난 구간은 건너뛴다.
- 범위 프로필과 비교(다룬 개념·강의에 없는 교재 개념·범위 밖 내용)는 코드가 노트에서 계산.
- Word: 부분마다 `▶ 시각` 링크(영상의 그 시각), 머리에 영상 QR 코드.

## 문제은행 · 문제 만들기

```bash
uv run dawoni units list                                   # 공통 단원표 (2015 개정 과학 I·II 초안)
uv run dawoni units add gift --subject "영재 물리" --group 물리 --toc 목차.txt
uv run dawoni bank add 문제집.pdf --kind problem_bank --title "OO 물리 문제집" --units phy1 \
    --pages 3-40 --key-pages 101-110 --unit phy1.1.1       # 등록만 (AI 호출 없음)
uv run dawoni bank chunk <자료ID> --pages 41-69 --key-pages 111-117
uv run dawoni bank ingest <자료ID> [--chunk 2] [--solve]   # 구간 DB화 (AI 구조화 — 풀이는 --solve 때만)
uv run dawoni bank solve <문항ID> … | --source <자료ID> [--chunk 2] [--redo]   # 풀이·해설 만들기
uv run dawoni bank add 교재.pdf --kind textbook --title "OO 물리학 I" --units phy1 \
    --level "고등학교 물리학 I"                              # 교재: 챕터 표를 제안해 저장 (AI 없음)
uv run dawoni bank chapters <자료ID> [--apply]             # 챕터 표 다시 제안 (+ 점검 보고)
uv run dawoni bank add 기출.pdf --kind mock_exam --title "2011 수능 물리I" --units phy1 \
    --key-pdf 기출_해설.pdf                                 # 해설 PDF가 따로 있으면 뒤에 붙여 한 자료로
uv run dawoni bank list [--unit phy1.1] [--check]
uv run dawoni bank export <문항ID> … --kind paper|key --title "단원 평가"
```

- **공통 단원표**: 과목마다 하나. 교재·문제집·기출의 문항이 모두 같은 단원으로 모인다.
  - 이름을 바꿔도 단원 ID는 그대로다. 문항이 있는 단원은 지울 수 없고 합치기만 된다(옛 ID는 새 ID를 가리킴).
  - 다른 체계(2022 개정, 영재 교재)는 목차를 붙여 넣어 만든다.
- **구간 DB화**: 두꺼운 책은 단원·쪽 범위로 나눠 넣는다.
  - 문제 쪽은 시험지 DB화와 같은 방법으로 구조화한다. 해설 번호는 구간 안에서만 맞춘다(문제집은 단원마다 1번부터).
- **DB화와 풀이는 따로**: DB화는 문항 구조화와 원본 정답·해설 옮겨 적기까지만 한다(단원 = 구간 단원).
  풀이·해설은 필요할 때 만든다 — 문항 하나, 고른 문항들, 구간·챕터 전체 ("풀이 없음" 필터).
  동형 제작에 쓰면 그때 먼저 풀어 저장한다. 여러 문항은 동시에 푼다(`parallel_questions`, 기본 3).
- **교재 챕터**: "1챕터 개념 | 1챕터 문제, 2챕터 개념 | 2챕터 문제 …" 구성을 챕터 표로 나눈다.
  - 제안은 AI 없이: PDF 목차(책갈피)가 있으면 그것으로, 없으면 쪽마다 개념·문제·해설을 분류해 묶는다.
    권말 "정답과 해설"은 챕터 제목으로 나누고, 챕터 제목을 단원 이름과 맞춰 단원을 제안한다. 강사가 표를 고친다.
  - 챕터 개념 쪽 → 그 단원이 붙은 **범위 프로필**(범위 프로필 → 단원으로 만들기에 그대로 쓰임).
    챕터 문제 쪽 → 문제은행 (풀지 않고).
  - 문항 번호는 챕터마다 1번부터 시작해도, 책 전체에서 이어져도 된다 (가장 길게 이어지는 번호 줄기를 문항으로).
    챕터 경계는 PDF 목차 → 앞쪽 글 목차("1. 속도와 가속도 ……… 2") → 강 제목 줄("제1강 등속운동") 순으로 찾는다.
  - 한 강에 문제 묶음("기본 문제", "학습 과제", "실전 문제" …)이 여럿이면 묶음마다 구간 하나 — 번호가 묶음마다
    1번부터 다시 시작해도 된다. 문항 영역은 묶음 제목에서 끊긴다.
  - 권말 해설은 문항 번호로(번호가 이어질 때) 또는 챕터 제목으로 나눈다. 묶음마다 1번부터인데 해설을 챕터
    단위로만 나눌 수 있으면 붙이지 않고 알린다 (다른 묶음의 같은 번호 답이 붙지 않게). 해설 읽기는 문항 유형과
    모양이 맞지 않는 답(서술형에 ⑤만, 객관식에 선지 번호 없음)을 버린다.
  - **DB화 전 점검**: 챕터 제안·"점검" 버튼이 구간마다 실제로 문항 번호를 찾아 빠진 번호, 두 번 인쇄된 번호,
    해설 쪽 없는 구간을 알린다 (AI 없음, AI 비용을 쓰기 전에 표를 고치게).
  - 쪽 하나가 구조화 검증을 끝내 통과하지 못해도 나머지 문항은 저장하고 그 쪽을 알린다. 다시 DB화하면 그 쪽만 읽는다.
    중간 결과(쪽 그림·쪽별 읽기)는 공유 폴더가 아니라 PC의 앱 데이터 폴더(`cache/bank-work/`)에 둔다.
- **해설 채우기** (풀이할 때): AI는 원본 답을 보지 않고 단원표 범위로 먼저 푼다. 풀이에 쓴 개념으로 단원이 정해진다.
  - 원본 답이 있으면 코드로 비교하고, 다르면 두 답을 각각 독립 검산해 **답 확인 필요**로 표시한다. 강사가 맞는 쪽을 고른다.
  - 원본 답이 없으면 두 번 풀어 비교한다.
  - 원본 해설이 충분하면 원본을, 없거나 짧으면 AI 해설을 쓴다. 원본은 지우지 않고 보관한다.
- **DOCX**: 학생용이라 출처를 넣지 않고 번호를 1번부터 다시 매긴다. "채점용 시험으로 만들기"를 하면 원본 정답·해설이 해설지로 들어간다.
- **함께 쓰기**: 문제은행·단원표·원본 PDF는 작업공간에 있으므로 모든 강사에게 같다.
  - 공용 목록 파일은 두지 않는다(목록은 PC별 캐시).
  - 문항·단원표는 판(revision)이 달라졌으면 저장을 거부한다.
  - 같은 자료를 두 PC가 동시에 DB화하지 못하고, 같은 문항을 동시에 풀지 못한다.
- **범위 프로필 → 단원으로 만들기**: 여러 교재에 걸쳐 단원을 체크하면, 그 단원으로 DB화한 교재 범위들을 합친 프로필 하나가 된다. 교재 DB화 때 단원을 고른다.
- **문제 만들기 → 동형**: 단원 트리에서 기준 문항을 골라 수치형·미지수형·조건 변형·다른 기법·확장 개념으로 만든다.
  - 승인하면 기준 문항의 단원·출처("다워니 제작 · 기준 …")를 이어받아 문제은행에 들어간다.
- **문제 만들기 → 새 문제**: 단원, 답 형태(객관식·ㄱㄴㄷ 합답형·단답형·서술형 소문항 수), 배점·난이도, 강사 아이디어를 넣는다.
  - 원하면 교과 외 개념을 말로 적는다. AI가 제시문용 정의·가정·유추할 내용으로 정리하고, 강사가 고친다.
  - 앱이 검사하는 것: 선지 5개, 합답형 정답 조합 = 참인 진술, 소문항 배점 합, 범위 밖 개념, 제시문 인용·사용.
  - 정답을 가린 채 다른 세션이 다시 풀어 확인한다. 서술형은 루브릭 초안까지 만든다.

## 혼자 쓰기 / 함께 쓰기 (M12)

```bash
uv run dawoni workspace init "<Google Drive 폴더>/다워니 물리" --shared --subject 물리   # 과목 팀 작업공간
uv run dawoni workspace status <경로>          # 모드·과목·동기화 폴더·충돌 사본
uv run dawoni workspace mode personal|team <경로>
uv run dawoni workspace subjects <경로> 물리 화학   # 과목 바꾸기 (비우면 모든 과목)
```

- **과목 팀**: 물리·화학·생명과학·지구과학 강사가 각자 팀이 되도록, 과목마다 작업공간(공유 폴더)을 따로 둔다.
  과목은 작업공간 표식 파일에 있어 그 폴더를 쓰는 모든 PC에 같고, 그 과목 단원표만 깔린다.
  문제은행·교재 DB·시험·해설·루브릭이 모두 그 폴더 안에 있으므로, 폴더를 공유하면 DB화한 것이 그대로 공유된다.

- 함께 쓰기: 여러 강사가 Google Drive·OneDrive·Dropbox 등 동기화 폴더 하나를 작업공간으로 연결.
  설정·기록·캐시·다시 그린 그림은 PC마다 앱 데이터 폴더에 두고, 작업공간에는 시험·답안·채점 결과만.
- 같은 시험을 다른 PC에서 열어 두면 시험 화면에 알림(시험 폴더의 `.inuse/`, 3분 지나면 무시).
- 해설·루브릭은 시험 폴더에 저장되어 팀 전체가 같은 것을 본다. 누가·언제 만들었는지 함께 보인다.
  같은 시험지 PDF를 다시 올리면 새로 만들지 않고 기존 시험(해설·루브릭 포함)을 연다.
  다른 PC가 같은 문항의 해설·루브릭을 만드는 중이면 막는다(`.locks/`, 30분 지나면 무시).
- 해설·루브릭은 문항 여러 개를 동시에 만든다(설정 `parallel_questions`, 기본 3). 시험지·교재 문항 구조화와 해설지 읽기도 쪽 단위로 동시에.
- 해설·루브릭·채점·제작 문항에는 만든 AI·모델이 색 태그로 보인다 (Gemini 파랑, Claude 주황, ChatGPT 청록).
- 동기화 프로그램이 만든 충돌 사본(`파일 (1).json`, `… conflicted copy …` 등)을 연결·설정 화면에서 알림.
